(before T17b/T17c/T19). 18 finders (six file groups x three lenses: client reality / secrets,

## R1 [high] `Spells/Measure.lua:700` -- The known deficit only grows between heals, so it can be far larger than the health actually missing and produce a false BELOW

**Fixed** in 12ba325 (review-measure)

*UPHELD 3/3*

**Scenario.** Measure is on. The druid takes 200 damage in a fight (WOUND on player, deficit=200), then regenerates to full out of combat. Natural regen, drinking or eating, a level-up refill and a resurrection fire no UNIT_COMBAT HEAL, so the deficit stays at 200 (it also stacks across fights with no cap at max health). The player then casts Healing Touch R2 (88-112) on themselves. Probe line 901 says UNIT_COMBAT HEAL looks effective, so the heal lands for only a few points (say 12). That is below min, deficitBefore=200 >= 88 and |12-200| > 1, so BelowHealText prints 'BELOW range'. This is exactly the false Q10 signal T12b exists to prevent. T12b's Facts say the deficit is 'a lower bound -- conservative for BELOW', but that is only true if every health gain arrives as a HEAL, which it does not. The same stale deficit gates the HoT BELOW at line 427.

**Evidence (as quoted by the finder):**

```lua
    if unit == "player" and action == "WOUND" then
        Measure.deficit = Measure.deficit + amount
        return
    end
    if unit == "player" and action == "HEAL" then

        Measure.deficit = math.max(0, Measure.deficit - amount)
...
    elseif d >= min then
        return "BELOW range"
```

**Skeptics:**

- UPHELD: The claim holds at 34d3509. In Spells/Measure.lua, `Measure.deficit` changes in only three places: line 703 adds each plain WOUND on player, line 709 takes off each plain HEAL on player (floored at 0), and line 769 resets it when Toggle switches measuring on. Nothing else touches it. There is no reset when combat ends and no cap at max health (the file never reads UnitHealthMax). No regen, drink, food, level-up or resurrection event is registered: Toggle (lines 757-760) registers only UNIT_SPELLCAST_SUCCEEDED, UNIT_COMBAT and PLAYER_TARGET_CHANGED. On the retail engine, natural health regen does not arrive as a UNIT_COMBAT HEAL, so health can come back while the deficit stays where it was, and it keeps growing across fights. The IsSecret and type guards at lines 687-697 only drop unreadable events. They do not stop a stale deficit. Nothing restricts this path to out of combat, and in any case the scenario only needs plain amounts, which the probe says UNIT_COMBAT gives in and out of combat. The verdict code does exactly what the reviewer says. BelowHealText (lines 281-290) returns "BELOW range" when amount < min, |amount - d| > 1 and d >= min. The HoT branch (lines 425-431) does the same using ticks[1].deficitBefore. So a self-heal on a player who is nearly full, after earlier WOUNDs that regen made up, produces a small effective amount against a large stale deficit and prints a false "BELOW range", the false downrank-penalty signal T12b meant to prevent. That makes the deficit an upper-biased overestimate, not the "lower bound -- conservative for BELOW" that T12b's Facts (docs/tasks/T12b-measure-attribution.md:46-48) assume. The spec only counted damage taken before switching on, not health regained without a HEAL event. BelowHealText (lines 281-290) checks |amount-d|<=1 first, then d >= min gives "BELOW range". So with a stale d=200 and an effective-looking HEAL of 12 from Healing Touch R2 (min 88), the output is "BELOW range", which is a false Q10 signal. No upstream guard saves it: the IsSecret and type checks at lines 687-697 only filter unreadable values, and the path runs in and out of combat alike because UNIT_COMBAT amounts are plain. The scenario is reachable: measuring stays on across fights and rests, and the tool's intended use is casting on yourself.
- UPHELD: The claim holds at 34d3509.
