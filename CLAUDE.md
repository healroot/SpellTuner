# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

**SpellTuner** (ManaDemon until 2026-09-27) is a World of Warcraft addon for **TBC Anniversary realms** (TBC Classic client, `## Interface: 20506`, Lua 5.1) that is being ported to **WoW: Forever** (Interface `16001`, the retail 12.1.5 engine with vanilla content; launch 2026-11-04). It helps healers manage mana: a time-to-OOM clock, per-rank efficiency tables, alerts, fight summaries, and a recorder / replay / coach / simulator / practice engine. Primary user is the author (Resto Druid); the TTO/advisor side is intentionally usable by any mana healer. Full design rationale and every debated decision live in **`docs/DECISIONS.md`** -- read it before changing model behavior.

**Two TOCs in one tree:** `SpellTuner_TBC.toc` is the whole TBC addon; `SpellTuner_Mainline.toc` is the Forever line (the suffix the client loads; `SpellTuner.toc` is its identical fallback, marker apart). The Forever line's three optional modules are LoadOnDemand sibling addons under `Modules/` (`SpellTuner_Recorder`, `_Replay`, `_Practice`). **The rule for the shared tree: client calls live in `Client/` only** (`Client/API.lua` is `MD.API`, the one adapter every shared file calls through; `Client/Probe.lua` sees raw values because that is its job). The port's architecture is `docs/FOREVER-PLAN.md`, its structure and milestones `docs/ROADMAP-FOREVER.md`, the verified facts about the two spell reference sites `docs/REFERENCES-FOREVER.md`, and each task `docs/tasks/T<n>-*.md`.

**One version, two installations** (the author's ruling, 2026-09-29, `docs/DECISIONS.md`): every TOC in the tree carries the same `## Version:`; the TOCs are the single source and `release.sh --set-version` bumps them together. Forever beta builds `0.16.x` and on (now `0.17.1`), **`1.0.0` at the Forever launch**, the TBC line never "alpha". `release.sh` builds a TBC package and a Forever package from the one tree, each installed into its own client.

**Current state:** version **`0.17.1`** on both lines (2026-10-04, T124: What if compares like with like -- the footer's numbers from the what-if book only -- and +Spell damage on both lines; 0.17.0, 2026-10-03, was One UI, T117-T123 from `docs/SPEC-one-ui.md`), installed in both clients. Next: the author runs `docs/TESTING.md` §50, §49 and §46.1 (the probe, which unblocks T103-T105, T108, T109 and the `BASE_CD_READS` flip); publishing is `secret-env run CURSEFORGE_API_TOKEN -- ./release.sh --publish --dry-run`, then without `--dry-run`, on the author's word. History of releases and tasks: `docs/HISTORY.md`; decisions: `docs/DECISIONS.md`.

On TBC the addon does:

1. **Time-to-OOM (TTO)** -- live projection of when mana hits zero, a one-line clock (`OOM 1:20 v  rest 2:10`; `FULL 0:45`) in a widget and/or datatext / broker. Class-generic. Rendered strings are **ASCII only** (no arrow/infinity glyphs) and never contain a bare `|`.
2. **Rank dashboard / Spells pane** (`/md`) -- per-rank mana efficiency, heal and HPS with +healing, talents and downranking penalties.
3. **Advisor** -- Innervate/mana-potion timing, "efficient rank shifted" toast, drink reminder.
4. **End-of-combat summary** -- one chat line per fight; own casts labelled `utility|shift|early|overheal|ok`; last **200** fights kept per character (`MD.cdb.fights`), fights under 4 own casts not kept.
5. **Self-calibration** (`Engine/Calibration.lua`) -- heals vs the model's prediction, drift reported (`/md calibrate`), **never fed back into the model**.
6. **Waste view** -- overheal and wasted mana by spell / role / class / target; pull budget.

Plus fight recording, replay, coaching, simulation, run recording and practice (specs below).

**Key docs.** Implement from the specs, not the `DESIGN-*.md` drafts: `docs/SPEC-v0.7.md` .. `SPEC-v0.15.md` (debate in `docs/debates/v0.7-sim/`), `SPEC-forever-ui.md`, `SPEC-next.md`, `SPEC-one-ui.md`; rulings per version in `docs/DECISIONS.md` §v0.x. **`docs/HISTORY.md`** is the session log: read its latest entries at session start, append a dated entry when a session ends with meaningful progress. **`docs/PLAN.md`** the agreed roadmap (tick items as they land); **`docs/TESTING.md`** what the author tests in-game; **`docs/TOOLS.md`** the `tools/` reference. `docs/tasks/` one file per task; `docs/review/` the independent reviews (R-items, B-items with "Fixed in"); `docs/PLAN-refactor-ux.md`, `docs/mockups/`, `docs/probe/` (reports by build), `docs/research/`.

## Conventions and constraints

- **No libraries.** Plain event frame, no Ace3. Keep it that way unless a hard need appears. **Host libraries borrowed, never shipped** (T97): LibStub and LibDataBroker are used only from a host that loaded them (EllesmereUI, ElvUI, Titan), never shipped, and host globals are read only under `Integrations/` (apicheck rule 11).
- **The model is event-driven; tickers only accumulate/render.** Never gate model updates behind UI visibility.
- **Widget visibility has a single owner** (`MD:UpdateVisibility` in `UI/Widget.lua`; the Forever clock's own `UpdateVisibility`) with the 90%/95% hysteresis of `MD.Visibility.Want` (`UI/Visibility.lua`). Do not call `Show()`/`Hide()` on the widget elsewhere. (The rule's `manaUsersOnly` included, T93; `UI/ClockView.lua` never shows or hides.)
- **API defensiveness:** the anniversary client's API surface is uncertain; wrap maybe-missing globals in `pcall`/existence checks (see `MD:On`, `ResolveCost`, `MD:HasBuff` for the pattern).
- **Any frame you style needs `"BackdropTemplate"`.** The backdrop mixin left the base frame in 2.5.x, so `UI.StylizeFrame` on a frame created without the template is a live error. `tools/wowstub.lua` installs the three backdrop methods only on templated frames and withholds them from its no-op fallback, so the harness fails the same way the client does.
- **`Data/SpellData.lua` values are best-effort and frozen** — any change must come from `/md verify` output or an in-game measurement, never from memory (costs were corrected that way on 2026-09-03; heal values for unlearned ranks are still `-- VERIFY`). Unverified formulas are listed in `docs/DECISIONS.md` §Open verification items.
- **Regen the client does not report** goes through `RM:Unreported()` only after an in-game `/md regentest` proves the API omits it (Dreamstate: proven). Adding a term the API already includes double counts.
- **Calibration never feeds the model.** `Engine/Calibration.lua` reports drift to a human; fixing it means changing `Data/SpellData.lua` or a formula, never scaling output by an observed ratio.
- **Lua multi-return trap:** `a and f() or b` truncates `f()` to one value. It bit twice in `UI/Summary.lua` around `Overheal:Split`; write the `if` out.
- **One escaping rule, one set of formatters** (T55 defined them, T60 moved the consumers): `MD.Text.Esc` doubles pipes only (a client name painted in the game's own font), `MD.Text.EscASCII` is the probe's reversible ASCII escape (copy boxes, reports, exports), `MD.Text.EscKeepColours` keeps well-formed colour codes; `MD.Util.K` / `Clock` / `Median` format numbers. A new file uses these instead of a local copy; `Client/Probe.lua` keeps its own (it must run with nothing else loaded).
- **Constants derived from one log are settings with provenance** (`db.oomConfidence`), not hard-coded truths — the first log was a level 61 dungeon on a level 64 druid.
- enUS only for now (drink-buff names in `UI/Advisor.lua` are literal English strings).
- **Debug logging:** `MD:Debug("category", fmt, ...)` with category in regen / mana / spend / tto / heal / cast / calib / combat / chat / sim / other; it is a no-op unless enabled in the Debug Console, so it is safe on hot paths. Log state transitions and inputs, not every tick.
- **New settings UI goes through `MD.UI`** (`UI/Style.lua`) as a row of the line's `MD.SettingsLine` (`UI/Settings_TBC.lua` on TBC, `UI/Dashboard_Forever.lua` on Forever), laid out by `UI/Settings.lua` (T119), not into the dashboard.
- **Forever-only look gates on `UI.THEMED`** (T69), never on a token being set; a token read (`UI.Hex("muted")`) is a colour. `tools/themecheck.lua` fails on a `UI.TEXT` gate in any UI file.
- **A style is paint only** (T94): no pane branches on `UI.STYLE` (`tools/themecheck.lua`).
- **A colour a style can change is a name** (T107): `UI.Tint` or a token read at paint, never a copy at creation (`tools/restylecheck.lua`).

## Verifying changes

There is no build system. A change is "verified" when:
1. `luac -p <file>` passes (any Lua ≥5.1 syntax check is fine),
2. the file is listed in its flavour's TOC (`SpellTuner_TBC.toc` for TBC; `SpellTuner_Mainline.toc` and `SpellTuner.toc` for Forever, and a module's own TOCs) in a position consistent with what it reads from `MD`, and
3. **make check** (tools/check.sh) is green: every suite under its flavours, apicheck 0 findings, textcheck, the selftests and the expected counts (docs/TOOLS.md section 1). A shared file never branches on `MD.API.client` (apicheck rule 10): a flavour difference is a value the flavour installs (T59).

Functional testing happens in-game: `/md verify` first (data + input snapshot), `/md fsrtest` for the five-second-rule anchor, then play. The neighboring `../ElvUI*` folders (if present in the parent AddOns checkout) are read-only reference code for datatext patterns.
